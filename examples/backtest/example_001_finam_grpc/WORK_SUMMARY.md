### 4. ⚠️ КРИТИЧЕСКОЕ: Debug проблемы "0 баров" (3+ часа расследования)

#### 4.1. Первоначальная "оптимизация" (ОШИБКА)

**Анализ:**
Zen thinkdeep определил, что загрузка медленная из-за маленького `chunk_days=7`:
- 492 дня ÷ 7 = 70 запросов × 3с = 210с (3.5 минуты на контракт)

**Действие:**
Увеличили `chunk_days=7` → `chunk_days=28` для ускорения на 75%

**Результат:**
❌ **ВСЕ контракты начали возвращать 0 баров!**

### 5. Оптимизация дат начала (ПРАВИЛЬНАЯ оптимизация) ✅

**Проблема:**
Все контракты запрашивались с фиксированной даты "2023-01-01", даже если начали торговаться позже.

**Решение:**
Умные даты на основе lifecycle фьючерса (18 месяцев до экспирации):

```python
# Было
{"symbol": "SiZ5@RTSX", "start": "2023-01-01", "expiry": "2025-12-18"}
# → 809 дней → 116 запросов

# Стало
{"symbol": "SiZ5@RTSX", "start": "2024-06-18", "expiry": "2025-12-18"}
# → 549 дней → 79 запросов
```

**Эффект:**
- Сокращение количества запросов: **~30-40%**
- Экономия времени: **~30-40%**
- Меньше запросов несуществующих данных

### 6. Исправление сортировки баров ✅

**Проблема:**
Ошибка при записи в каталог:
```
ValueError: Data should be monotonically increasing based on `ts_init`
```

**Решение:**
Двойная сортировка (сначала ts_event, потом ts_init):
```python
# Было
sorted(bars_dict.values(), key=lambda b: b.ts_event)

# Стало
sorted(bars_dict.values(), key=lambda b: (b.ts_event, b.ts_init))
```

## 🔍 Ключевые открытия

### 1. Документация API != Реальность

**Документация:** "M1 timeframe - max 30 days per request"
**Реальность:** ~7-9 дней максимум (тестирование показало)

### 2. chunk_days - это лимит, не оптимизация

`chunk_days` существует для **обхода API лимитов**, а не для ускорения.
Попытка "оптимизации" (7 → 28) привела к **полному отказу** загрузки.

### 3. Медленная загрузка != Проблема

- 1-2 часа для загрузки ~1M минутных баров = **нормально**
- 27 контрактов × 365-549 дней × M1 = огромный объем данных
- "Оптимизация" без измерений может **сломать** working code

### 4. Систематический подход к debug

**Процесс:**
1. Изолировать проблему (один контракт)
2. Тестировать гипотезы последовательно
3. Создавать специализированные тесты
4. Документировать результаты
5. Находить root cause, не симптомы

**6 диагностических скриптов → ~30 минут → точная причина найдена**

### API Limits (реальные, проверенные)

- **M1 (1 минута):** ~7-9 дней за запрос ⚠️ КРИТИЧНО
- **M5, H1:** вероятно ~30 дней (не тестировалось)
- **D, W, MN:** без ограничений

### Дедупликация

```python
# Ключ уникальности
key = bar.ts_event  # timestamp события на бирже

# При дублировании
saved_bar = max(duplicates, key=lambda b: b.ts_init)  # самый свежий
```

### Chunking механизм

```python
total_days = 492
chunk_days = 7
chunks_count = ceil(total_days / chunk_days)  # 71 чанк

for chunk in chunks:
    bars = await request_single_chunk(start, start + 7_days)
    all_bars.extend(bars)
    await asyncio.sleep(0.5)  # rate limiting
```
